01읽는 방법

위에서부터 순서대로. 건너뛰면 뒤에서 막힌다.

글마다 틀이 같다. 이 모듈이 하는 일을 한 문장으로 적고, 읽을 파일과 줄 범위를 정하고, 실제 DB 행을 보는 쿼리를 돌린 다음, 메서드 하나를 끝까지 따라간다. 그 뒤에 함정을 모아 두고 자가진단으로 닫는다. 자가진단을 넘지 못했으면 다음 글로 가지 않는다. 뒤의 글이 앞의 글을 딛고 서 있기 때문이다.

이 시리즈의 전제

0~2단계가 전체 Java 파일의 9% 남짓(671 / 7,814)인데, 현업에서 손대는 일의 대부분이 그 안에서 일어난다. 나머지는 필요해질 때 모듈 지도를 꺼내 보면 된다.

파일 수는 2026-10-12 커밋 기준 Java 파일 실측. 7월 초판 뒤로 전체가 1.3배쯤 불어나서 모든 단계를 다시 쟀다.

6단계는 마지막까지 미룬다

가장 어렵고 가장 자주 바뀌는 자리다. 필요해지기 전에는 손대지 않는다.

03발행된 글

순서대로 읽는다.

1어드바이저 코드베이스 학습 가이드 시작점
2인증 · 권한 · 메뉴 체계 0단계
3stt 모듈 — 모듈 구조 패턴 체득 1단계
4evaluation 모듈 — 핵심 업무 도메인 2단계
5recording · sttanalytics — 데이터 인입과 분석 3단계
6ai — execution · prompt · routing (예정)

1번 글이 전체 경로와 0단계 세 모듈을 다루고, 2번이 그중 권한 체계를 깊게 판다. 3번부터는 모듈 하나에 글 하나씩이다.

04공통 루틴

모듈이 61개지만 생김새가 같아서, 여는 법은 하나면 된다.

모듈 하나를 읽는 5단계
1) 모듈 지도에서 한 줄 설명 확인
2) entity/        이 도메인이 다루는 "명사"가 무엇인지
3) DB SELECT      그 테이블 실제 데이터 10건을 눈으로 확인   ← 가장 중요
4) controller/    밖에서 무엇을 요청할 수 있는지 ("동사")
5) service/impl/  관심 있는 메서드 하나만 끝까지 추적
모든 모듈이 따르는 디렉토리 구조
{module}/
  controller/   REST 진입점       @RestController
  service/      인터페이스        IXxxService
  service/impl/ 구현체            XxxServiceImpl
  repository/   DB 접근           JpaRepository
  entity/       테이블 매핑       @Entity
  dto/          요청·응답 객체
  event/        도메인 이벤트
  listener/     이벤트 수신
  scheduler/    주기 실행

3번을 건너뛰지 않는다

세 번째 단계를 건너뛰고 싶은 유혹이 매번 온다. 순서를 바꿔 보면 안다. 실제 행 열 개를 눈으로 본 뒤에 엔티티를 다시 열면, 조금 전까지 추상적이던 컬럼 이름이 전부 아는 얼굴이 되어 있다.

■기억할 것

  1. 전부 이해하는 건 목표가 아니다. 필요한 자리에 빠르게 도달하는 능력이 목표다.
  2. 작은 모듈부터. 큰 모듈에서 시작하면 패턴 대신 피로가 남는다.
  3. DB 를 먼저 본다. 명사(entity), 실데이터, 동사(controller), 추적(service)의 순서다.
  4. 글마다 자가진단이 있다. 넘지 못했으면 다음 글로 가지 않는다.
