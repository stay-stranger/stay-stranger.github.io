01읽는 방법

위에서부터 순서대로. 건너뛰면 뒤에서 막힌다.

각 글은 모듈 하나를 같은 틀로 다룬다. 이 모듈이 하는 일 한 문장, 읽을 파일과 줄 범위, 실제 DB 데이터를 보는 쿼리, 메서드 하나를 끝까지 따라가는 추적, 함정 모음, 자가진단 순이다. 글 끝의 자가진단을 통과하면 다음 글로 넘어간다.

이 시리즈의 전제

0~2단계가 전체 Java 파일의 약 9%(671 / 7,814)인데, 실무의 대부분이 이 9%에서 나온다. 나머지는 필요해질 때 모듈 지도를 보고 찾아가면 된다.

2인증 · 권한 · 메뉴 체계 0단계

1번 글이 전체 경로와 0단계 세 모듈을 다루고, 2번이 그중 권한 체계를 깊게 판다. 3번부터 모듈 하나에 글 하나다.

04공통 루틴

모듈이 57개지만 전부 같은 구조라, 접근법도 하나면 된다.

모듈 하나를 읽는 5단계
1) 모듈 지도에서 한 줄 설명 확인
2) entity/        이 도메인이 다루는 "명사"가 무엇인지
3) DB SELECT      그 테이블 실제 데이터 10건을 눈으로 확인   ← 가장 중요
4) controller/    밖에서 무엇을 요청할 수 있는지 ("동사")
5) service/impl/  관심 있는 메서드 하나만 끝까지 추적
모든 모듈이 따르는 디렉토리 구조
{module}/
  controller/   REST 진입점       @RestController
  service/      인터페이스        IXxxService
  service/impl/ 구현체            XxxServiceImpl
  repository/   DB 접근           JpaRepository
  entity/       테이블 매핑       @Entity
  dto/          요청·응답 객체
  event/        도메인 이벤트
  listener/     이벤트 수신
  scheduler/    주기 실행

3번을 건너뛰지 않는다

실제 데이터를 보면 코드가 갑자기 읽힌다. 코드만 보면 추상적이라 머리에 남지 않는다.

■기억할 것

  1. 전부 이해하는 건 목표가 아니다. 필요한 부분에 빠르게 도달하는 능력이 목표다.
  2. 작은 모듈부터. 큰 모듈에서 시작하면 패턴이 아니라 피로만 남는다.
  3. DB 를 먼저 본다. 명사(entity) → 실데이터 → 동사(controller) → 추적(service).
  4. 글마다 자가진단이 있다. 통과하지 못했으면 다음 글로 넘어가지 않는다.
