도식

03[0단계] core — 기반

모든 API 응답의 껍데기. ApiResponse.success() / badRequest() 형태가 전체 컨트롤러에서 반복된다. 이걸 알면 아무 컨트롤러나 열어도 응답부가 바로 읽힌다.

3.2 core/config/LocalSecurityConfig.java (391줄)

"이 URL은 로그인 없이 되나?"의 답이 전부 여기 있다.

주의: 보안 설정이 프로파일별로 3개 파일로 나뉘어 있다.

  • requestMatchers(...).permitAll() — 인증 없이 열린 경로
  • .authenticated() — 로그인만 요구하는 경로 (대부분이 이것이다)

2026-10 기준으로 알아둘 것

  • API 인가는 인증 여부로만 한다. @PreAuthorize 1,600여 건 중 isAuthenticated() 1,495건, hasFeature(...) 110여 건, hasRole('ADMIN') 1건. 역할 문자열을 코드에 박지 않는다(CRITICAL 19 · 27).

  • 자세한 구조는 02 권한 가이드.

함정

  • @PreAuthorize 를 쓰려면 @EnableMethodSecurity(prePostEnabled = true) 가 필요하다 — 보안 설정 3개와 permission/config/PermissionSecurityConfig 에 붙어 있다
  • 새 DB 구축 시 dynamic_roles id=1/2/3 시드 필요 — aws-deploy/README.md 는 seed_dynamic_roles.sql 을 먼저 실행하라고 하는데, 그 파일이 저장소에 없다(2026-10-12 확인). V10.2__create_dynamic_roles_table.sql 과 mariadb/beforeEachMigrate__bootstrap_chat_execution_cancel_roles.sql 이 관련 시드를 담고 있으니 신규 DB 구축 전에 빈 DB 로 Flyway 를 끝까지 돌려 확인할 것

5) service/impl/EvaluationSchedulerServiceImpl.java  평가 실행 핵심 ← 길다, 아래 메서드만
      - checkAndExecuteSchedules()   (445줄) 실행 폴링 진입점
      - resolveScheduledTargets()    대상 선정 규칙 — 실제 구현은 EvaluationExecutionServiceImpl 251줄

핵심 개념 — 상태 전이

도식
PENDING → DATA_READY → IN_PROGRESS → COMPLETED
                            ↓
                   SKIPPED / FAILED / EXPIRED

DATA_READY 상태만 평가 대상으로 선정된다. 이것만 기억해도 절반이다.

핵심 개념 — 대상 선택 방식

값화면 표기조회 조건
CONSULTANT상담사 기준계획에 할당된 상담사의 통화
SCHEDULE연동 대상 기준출처가 EXTERNAL_SYNC 인 통화

헷갈리기 쉬운 것 — 스케줄러가 6개다

평가 계획에 설정한 Cron은 이 중 1개에만 적용된다. 나머지는 24시간 상시 동작한다. (2026-10-12 재확인, 전부 그대로)

실행 판정은 "지금이 Cron 시각인가"가 아니라 "next_execution_at 이 현재를 지났는가"다. next_execution_at 은 배치 정상 종료 후에만 갱신되므로, 서버가 배치 도중 죽으면 갱신이 안 되어 재기동 후 시간대와 무관하게 1회 실행될 수 있다. → "설정한 시간 외에 평가가 돈다"는 문의의 대표 원인.

       lock_owner, lock_expire_at, NOW() AS now
FROM evaluation_schedule_config;

■기억할 것

  1. 전부 이해는 불가능하다. 목표는 필요한 부분에 빠르게 도달하는 능력이다. 0~2단계가 전체의 약 9%다.
  2. 모듈은 전부 같은 구조다. entity 로 명사를, DB 로 실데이터를, controller 로 동사를 보고 service 메서드 하나를 끝까지 추적한다.
  3. DB SELECT 를 건너뛰지 않는다. 실제 데이터 10건을 보면 코드가 갑자기 읽힌다.
  4. 6단계는 필요해지기 전에 손대지 않는다. 가장 어렵고 가장 자주 바뀐다.
